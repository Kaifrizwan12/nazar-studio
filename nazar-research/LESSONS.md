# nazar-research lessons

- 2026-11-22: Research was scattered (each kit had its own "research" step, and packaging work used memory for the shelf). Now every kit's research runs through this kit with a profile, into one growing `research/` folder per project, and a reference dataset per kit replaces "I know what the category looks like".
- 2026-11-22: The method itself was researched before writing it (plan-reflect loop, snowballing, saturation, SIFT, semiotic codes, distinctive-asset audit, triangulation); `references/method.md` names each source so it can be re-checked.
- 2026-11-23: Research covered the brand and the kits but not each deliverable, and a mark serving two worlds (a house and its artist) was researched in one world only. Now step 0 maps every deliverable in scope with every world it touches (`dataset.py plan … --deliverables`, `deliverables/<ID>.md`: precedents per world, specs, details); `report` lists rows still todo and worlds with no findings; the playbook blocks design of a piece while its row is todo. Covered in `dataset.py --selftest`.
- 2026-11-23: On a real job the owner had to steer the researcher many times by hand (no real products of the category; one product family only; single-source kinds; thumbnails; images but no written findings; no stop rule; a hand-written spawn prompt that replaced the profiles). Now: `dataset.py spawn` writes the prompt; `plan --formats` sets a minimum per product format; the researcher writes findings and `progress.md` every round; `dataset.py stop` records why each kind stopped; `report --strict` gates thin kits, formats, single-source kinds, one brand > 25%, low-res photo kinds, template files and todo deliverables, unless each is written in gaps.md. Run on that job's folder, the gates flagged exactly the faults the owner had pointed out. Covered in `dataset.py --selftest`.
