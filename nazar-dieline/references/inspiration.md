# Inspiration: where the best structural references live, and how to collect them

Order matters. Go archive → craft → awards → libraries → feeds, and stop when you have enough reasons, not enough pictures.

## 1. Archives and collections (first)
| Source | Look for |
|---|---|
| Museum of Brands, London (museumofbrands.com) | How packs evolved; what stayed recognisable across redesigns |
| Cooper Hewitt, packaging design type (collection.cooperhewitt.org) | Designed objects, folded structures, labels |
| The Met: *Origata tehon* and Japanese folding models (metmuseum.org) | Ceremonial wrapping as structure |
| Kyushu University Library origami guide (guides.lib.kyushu-u.ac.jp) | The history of folding in Japan, with digitised sources |
| Internet Archive: Oka, *How to Wrap Five Eggs* (borrowable, per secondary sources: verify) | Natural-material packs |
| Royal Collection Trust, paan boxes (rct.uk) | Compartment logic, ritual containers |
| Tasveer Ghar matchbox labels (Google Arts & Culture) | Drawer-and-sleeve graphics at tiny scale |
| Japan Package Design Association, yearbooks *Package Design in Japan* (jpda.or.jp) | Biennial awards since 1985; Grand and Gold winners archived [SRC] |

## 2. Award galleries (for the current bar, never to copy)
| Source | Look for |
|---|---|
| Dieline Awards (thedieline.com): winners by year and category; "Best Use of Paper" and structural categories | Packaging judged by structural, design and brand experts [SRC] |
| Pentawards (pentawards.com): the structure and sustainability categories | Global packaging award; check the official winners gallery |
| iF Design Award and Red Dot (packaging disciplines) | Engineering-minded entries, often with structure shown |
| D&AD Pencils, Packaging Design | The idea-led end |
| JPDA (above) | Restraint, material honesty |

## 3. Structural libraries (for mechanisms and codes)
Diecut Templates (parametric, SVG/DXF/PDF), Pacdora FEFCO library, Boxshot ECMA and FEFCO pages, and converters' own style guides (FBA *Box Styles Basics*, FEFCO Code PDF) [SRC]. Use these to name a mechanism and check its geometry, and check each library's licence before using a file.

## 4. Feeds (last)
Packaging of the World, Behance and Pinterest boards are useful for scanning volume, and dangerous for originality. Never start here. If a reference only exists on a feed, trace it back to the studio's own case study and credit it.

## How to collect references (the rules)
1. **Save to the client's private `research/structure/refs/`**, never into a kit, deliverable or public repo. Other people's pack photos are their copyright.
2. Name files `<yyyy-mm-dd>_<source>_<project-or-object>.jpg` and keep a line in `research/structure/refs.md` for each: **URL, maker/studio, year, what it teaches** (one line), and an evidence tag ([ARCH] / [SRC] / [TREND]).
3. **Study the mechanism, not the look.** For each ref, sketch the dieline you think it uses. If you can't, it's a picture, not a reference.
4. **Credit in presentations** when a ref is shown ("Reference: *Studio, Project, Year*"). Show refs to explain a mechanism, never as the proposal.
5. **Distance check before routes:** put your route next to its closest reference. If a stranger would call it a copy, kill it or push it further.
6. If you have a browser available, use it to open galleries and save the specific images; otherwise collect links with the same notes. Either way, the log line is what matters.
