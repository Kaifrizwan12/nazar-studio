# Lessons from real work (nazar-pitch)
Format: date · what happened · evidence · change made. Kept generic on purpose: no client names or private data.

- 2026-11-21 · A project-specific publish script hand-copied files into the client and portfolio folders and removed the old copies · Stale renders could reach a sent folder, and nobody could say which portfolio panels had changed. · Added `engine/handover.py`, a packager driven by one manifest. It fails on missing or stale sources, parks old files instead of deleting them, writes README.txt and SHA256SUMS.txt, and prints the panels to re-upload. See `references/handover.md`, `references/research_handover.md` and `engine/test_handover.py`.
- 2026-11-21 · The packager's demo dry run against a delivered portfolio folder · It reproduced the client folder exactly (56 of 56 files the same, zip contents the same). It also found that every panel is 2880 px wide, while Behance's help says 2800 px or smaller, and that the 768×576 cover fallback is below Behance's 808×632 minimum. · The packager warns on both. Still open, for the owner to decide: should the story engine render 2800 px panels and drop the 768×576 fallback? `nazar-story` is unchanged.
- 2026-11-21 · A "/" inside a label (e.g. "A/B") made a surprise sub-folder · Found by the self-test. · A slash inside a template value now becomes "-". Only a slash written in the template itself makes a sub-folder.
- 2026-11-21 · A re-zipped folder had different bytes but the same files · Rebuilding would have parked a good zip for no reason. · The packager now compares zip contents (names + CRC-32) and keeps a zip whose contents already match.
