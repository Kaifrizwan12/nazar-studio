# Lessons from real work (nazar-voiceprint)
Format: date, what happened, evidence, change made. Generic on purpose: no client names or private data.

- 2026-11-16 · Stroke layer on slides · A 28-piece social-slide archive read as "sketchy, hatching, line-led drawing". Evidence: ink fraction, line width and two-tone share did not separate slides from line art (slides 0.05-0.43 ink, 2-84 px width; engravings 0.3-0.5, 2-4 px; the two-tone test overlapped). No numeric gate was reliable. · `portfolio.py` now skips the line layer unless `--line` is passed, and also drops line phrases from the composition reading.
- 2026-11-16 · Biggest habits missing · The same archive's strongest habits (4:5 canvas in 86% of pieces, a light/dark two-ground system) were not reported. · `portfolio.py` now reports FORMAT and GROUNDS first.
- 2026-11-16 · Declared AI-assisted work · The person stated the work was AI-assisted, human-directed and client-approved. The date gate would have held it all back. · SKILL.md: the person's word counts; record the declaration and label the pattern "recent (AI-assisted era)".
- 2026-11-16 · Generated pieces looked AI-made · Pieces with redrawn gradients and a stand-in logo read as AI; the same pieces on the archive's exact backdrop and logo files did not. · Pattern template and SKILL.md: an "Exact assets" line; place as-is, never regenerate.
- 2026-11-16 · Kit rule vs brand practice · `nazar-backdrops` rule 5 bans gradients and glows behind type, but this brand's real backdrops use both. · Open: the rule is a studio default and an AI-tell check; a brand's own exact backdrop file should override it. Needs wording in nazar-backdrops.
- 2026-11-16 · Font named by eye · The headline face was assumed to be Anton and the person said it was wrong. A new matcher found Anton closest of 799 installed faces (0.86 shape overlap) but 7% wider, a near match and not a match. · New `nazar-type/engine/font_match.py` (self-tested at 0.95 on a known font); type SKILL rule 7a; pattern template has a Type line marked unconfirmed.
- 2026-11-16 · Directions did most of the work · A fresh agent with only the person's directions and the exact backdrop and logo files made good on-brand slides (0.62 on the pattern checks, losing only on canvas size and palette share). The pattern added the 4:5 habit and a measurable check, not better design. · README states this plainly; improve.md describes the loop.
- 2026-11-16 · Copy gap · The pattern-driven draft had less Roman Urdu (0.0-0.12 Hindustani share) than the no-kit run (0.0-0.14, more natural lines), and no engine reads text inside images. · SKILL.md: ask for slide copy as text; social SKILL: the lint is English-only.
- 2026-11-16 · Accent contrast · Brand blue on the light ground is 3.0:1, large text only. Both runs set small button labels on it. · Colour SKILL: say which sizes an accent may be set at.
- 2026-11-16 · Leaked split · The first pattern was measured from a split that overlapped the later held-out set. · `score_pattern.py --build` measures only from the training folder; improve.md: never let held-back pieces into the pattern.
- 2026-11-16 · Assets counted as pieces · A bare logo file and mascot cut-outs were scored as designed pieces. · Split excludes brand assets; documented in the case study.
- 2026-11-16 · The prompt carried the look · With a strong human prompt (4:5 crop of the exact backdrops, headline and subline rules, no buttons, references), a fresh agent with no kit scored 0.90 and made the best slides; the with-kit set scored 0.85. The kit's measured contribution is small when the prompter already knows their habits. · `score_pattern.py --prompt` writes the pattern as that prompt; README says plainly that the directions and exact files do most of the work.
- 2026-11-16 · Invented devices pass every check · A filled "Verify karo" button on a slide passed colour, ground and palette though the archive has none. · New `device` check in `score_pattern.py`: flags a filled accent button unless 10%+ of the archive's pieces use one.
- 2026-11-16 · Backdrop recreated, not used · The first with-kit slides stretched a square backdrop file to 4:5. The exact files can only be cropped. · The case study crops the 900x1600 story backdrops to 900x1125; the format check now compares ratio, not pixels.
- 2026-11-16 · Palette check scored exact-file slides low · Dark slides on the exact backdrop failed the palette check because the pattern only knew border colours. · `score_pattern.py --build ... <asset files>` adds the exact files' colours; the exact assets define the palette.
- 2026-11-16 · Accent check penalised slides without an accent · Only 57% of the real pieces carry the accent, so absence is part of the habit. · Accent check passes absence when the archive's own presence rate is under 80%.
- 2026-11-16 · Scores saturate · Once the checks matched the archive, the expert and kit runs both scored 1.00. · README says the score is a gate; the open need is a human pick test and a visual review.
- 2026-11-16 · Brand accent fails large-text contrast · The brand blue on the light ground is 2.9:1, under 3:1, and every run used it for headlines. · `chain_check.py` flags it and suggests a darker blue for new type only.
- 2026-11-16 · Fresh agent with the skill (all kits installed, relevant ones named, checks and QA inside its task) · Its slides passed every pattern check and its own QA, and its headline blue was the only one that reached 3:1 on the light slides (3.2:1, against 2.5:1 for the expert-prompt run). It also reported what got in its way: the accent check measured the archive accent, not the colour on the slide; QA was by eye because no QA tool existed; copy.json errors were silent; score_pattern had no help; font_match was slow and cannot name a small sans. · `chain_check.py` now measures the accent type actually used against the ground beside it and suggests a darker value from that ground, and stops on a missing input; new `nazar-core/engine/qa_views.py`; `score_pattern.py -h`; `font_match.py` runs in about 5 s (coarse pass, then the best 40).
- 2026-11-16 · A noisy QA tool is worse than none · The first `qa_views.py` flagged dot-grid specks as tiny text and every footer as near the edge. · Merge words into lines, ignore specks, measure the tight ink box, exempt footers; tested on a deliberately bad slide (it flags misaligned and crowded text and tiny type, and is quiet on the real slides).
- 2026-11-16 · The agent redrew a device from the archive · It rebuilt the translator card from shapes and said so. A device is not a supplied file, but its icons are not the originals. · Kept as an open note: check redrawn devices against the originals.
- 2026-11-16 · A continuous fit score didn't discriminate either · Added a FIT measure (nine structural features within the archive's own 2-SD range). Real held-out pieces scored 0.92, the generated sets 0.89 to 0.95: the archive is too varied (chat bubbles, memes, cards, headlines) for any slide to look like an outlier. · Kept as an advisory outlier detector and labelled so; the discriminating tests are a non-expert prompter with and without the skill, and a human pick test.
- 2026-11-16 · Token claim · "Skills save tokens" holds for carrying the knowledge (about 2.1k always loaded against about 121k pasted) and for big inputs (a 0.4k engine report against about 58k to look at 28 pieces), not for a full run that checks itself (117k against 57-59k without the skill). · README states both.
- 2026-11-16 · Casual prompt with the skill · A casual prompt (no format, no habits) with the skill installed gave 4:5 slides on a light and a dark ground, because `portfolio.py` measured both in the archive; the casual prompt without the skill came out square (0.80). The agent fixed a failing blue headline itself (2.6:1 to 3.8:1), found `qa_views.py` clean, and reported gaps. · Fixed: `qa_views.py -h` and its output argument; backdrop-to-format guidance for square or small files (crop never scales, but 1080x1080 to 4:5 is resampling and must be labelled); a gradient-ground rule for accent type; intake questions only for what the prompt hasn't said.
- 2026-11-16 · The skill against a runtime agent · The same full job (measure the archive, four slides, contrast, font, QA) from a casual prompt: with the skill 105k tokens, 32 tool calls, 3.7 min; without it 117k, 44 calls, 5.8 min and 10 scripts (about 340 lines) written to measure, font-match, check contrast and QA. Both passed every check with good slides. · README claims about 10% fewer tokens and 35% less time on this job, and says the larger savings (stylometry, dielines, tracing, font coverage) are an expectation, not a measurement.
- 2026-11-16 · The no-skill run's honest differences · It chose DIN Condensed Bold thickened as a font stand-in, darkened the light-ground blue to 3.2:1 after measuring it, and used small caps kickers above the headlines; it never measured letter spacing or the handle face. · Left as is: both approaches reach a comparable result; the skill's edge here is speed, repeatability and tested engines.
- 2026-11-16 · Fast path · After `studio.py learn` and `check` were added to the top of nazar-core/SKILL.md, the same casual-with-skill job fell from 105k tokens, 32 calls, 3.7 min to 74k, 19 calls, 2.4 min (the no-skill run: 117k, 44, 5.8). The transcripts showed why the first version saved only 10%: rebuilt tools were cheap, most spend is shared work and the conversation re-read on each call. · The saving is in fewer calls and less reading; README says so.
- 2026-11-16 · Fast-path report, new weaknesses · Every agent re-wrote the backdrop crop and the logo multiply (and got the edges wrong at first); `check` gave advice for new type only and measured one ground per slide; `learn` read photo posts into the layout line ("image/shape-led"); the lint is English-only and said nothing about the Roman Urdu it skipped; the pattern score passed a slide with overlapping text. · New `place_asset.py`; `chain_check.py` reports contrast by height and the best band for existing type, and says how much of the copy wasn't linted; `portfolio.py` reports flat versus photo-led pieces and lays out the flat ones; `qa_views.py` flags overlapping lines (a merged, tight stack still needs eyes; a tall-block check was tried and removed as noisy).
- 2026-11-16 · Reading slide text · No engine read text inside images, so copy.json was always hand-written. macOS ships a recogniser (Vision); a 40-line Swift helper (`ocr_mac.swift`, compiled once to ~/.cache/nazar) reads slides with nothing installed. Known-answer test on 20 slides with known copy: 282 of 287 words found (98%), including Roman Urdu with language correction off. · `read_text.py`; `studio.py check` builds copy.json when it is missing. Non-Mac machines need tesseract, else copy.json by hand.
- 2026-11-16 · Small-body-font matching · The first matcher (thresholded shapes in a square) named the right family but often the wrong weight (Avenir Next Bold read as Heavy). Rewritten on greyscale ink at the true aspect ratio with a stroke-weight term; the earlier "Space Grotesk Medium" test was a variable font that renders as Light, so the engine had been right. Known-answer test on 24 random installed faces at 26 px: first for 13, in the top 3 for 20. · Small text now returns a shortlist and says so; look-alike families (Helvetica, Arial, Helonia) can't be told apart at that size.
- 2026-11-16 · A habit score that ranks good work · Tried a nearest-neighbour typicality on a structural fingerprint. It flags structurally unusual slides but missed an off-brand purple slide (the colour gate catches that) and can't separate good from better. · Kept as an advisory outlier flag. Still open: it needs a human pick test.
- 2026-11-16 · Teaching other Claudes · A skill read by someone else's Claude needs an install check and a first-time list. · `selftest.py`, a "first time" list at the top of nazar-core/SKILL.md, and README sections for a person and for a Claude.
- 2026-11-16 · Fair six-brief test, three conditions · Same terms for all (mascot, devices, real handle allowed). By eye and by the first blind judge the no-skill "measure and check" run (B) was richer and closer to the brand than the skill run (C): B had the lanyard ID card, stars, ticket, alert window and the mascot on most slides; C was plainer with empty areas. Tokens: A casual no skill 103k, C skill 112k (rules and kit docs about 7.5k and engine reports about 3.7k read; code written about equal). · The fast path pushed numbers and checks and skipped looking at the archive. `learn` now writes devices.md to fill in after looking at the contact sheets, and `check` warns when it is empty. An objects-per-slide measure was tried to catch plainness and dropped: it didn't separate B from C and was noisy.
- 2026-11-16 · Skill-run report, more fixes · The contrast check counted the mascot's blue as accent type (reported 1.7:1): it now keeps only text-like lines. Its darker-blue suggestion could equal the failing colour: it now starts from the worst band's colour with margin. The device rule flagged a chat bubble the archive itself uses (4% of pieces): it now fails only a device the archive never uses. `place_asset.py mascot` removes white paper by flood fill (multiply turned yellow shoes olive). `learn` took over two minutes with no progress: OCR now runs in one process (42 s for 28 pieces) and prints progress. A strike-through that slanted off its text only shows at 100%: `qa_views.py` now writes native-size detail crops.
- 2026-11-16 · The fair test's blind judges · Two judges scored 28 shuffled slides (10 real held-out, 18 generated). Brand fit: real 3.70, B (no skill, measure and check) 3.08, C (skill) 3.00, A (casual, no skill) 2.83; quality B 3.50, C 3.42, A 3.33, real 2.70. They identified generated slides 98% of the time: too tidy and formulaic, the same polished mascot and props, tidy Hinglish; real pieces are blunter, messier and more varied (photos, partner logos, text walls). C tied B on look at 35% fewer tokens, 44% fewer calls, 47% less time. · `learn` now adds a VARIETY instruction; devices.md forces a look at the archive's devices; an improver agent is building `devices.py` and `draw.py`.
- 2026-11-16 · Improver agent · The owner directed an agent to fix the gaps itself. It wrote `devices.py` (finds recurring non-text objects across pieces: known-answer test on 10 synthetic pieces, sticker A in 7 of 10 and B in 8 of 10, exact, no false groups, 1.1 s; on the real 28-piece archive 19 groups in 3.6 s, finding the logo lockups, app-store badges, outline star sticker, the mascot with a sign, ID cards and a partner roundel, and missing the chat bubble) and `draw.py` with `test_draw.py` (ink-aligned text within 2 px; a level strike-through centred on the text, which is the fault a skill run's receipt slide had). · Integrated into `learn` and the core skill. Still weak: UI-style devices, mascot poses only partly grouped, no edge-fringe un-mixing on a mascot cut-out.
- 2026-11-16 · Improved skill run (C2) · After the devices and draw kits were integrated, the same casual six-brief job took 99k tokens, 23 calls, 6.1 min (was 112k, 35, 7.3). The agent reported: the contrast check still counted filled chat bubbles as accent type (now: solid blocks over 70% fill are shapes, not type); filling devices.md by hand was friction (now `studio.py devices <out> "a; b; c"`); learn's device candidates were mostly logo and noise and missed UI-style devices (chat bubble, translate card, alert popup, store badges): still open; draw.py arrow and bubble need trial and error to place: fine once positioned.
- 2026-11-16 · Three rounds of blind judging, three interventions · Brand fit (1 to 5), skill vs the careful no-skill run: round 2 3.00 vs 3.08; round 3 3.17 vs 3.33; round 4 2.67 vs 2.83 (skill improved and skill with `nearest` both 2.67). A forced look at devices, a variety rule and adapting the nearest real piece did not move fit beyond noise (six slides, one judge); the skill stays about 0.15 below, within noise, at 35 to 60% lower cost. The no-skill run that looked best iterated for 63 calls and 14 minutes. · New: `check` writes compare_*.jpg (each slide beside its structurally closest real piece) as a craft pass; `draw.py` gains `alert_dialog`, `line_chart`, `tilt_paste`; detail crops are written next to the sheet. Effect of the craft pass is measured in the next round.
- 2026-11-16 · Clutter and invented devices, measured · The owner said the skill's slides were cluttered, had misplaced text and elements not in the archive. The device segmenter shows it: real held-back pieces average 3.3 objects with 33% unfamiliar ones; casual no-skill 6.8 and 61%; no-skill measure-and-check 7.2 and 63%; skill first version 7.7 and 59%; skill improved 6.0 and 44%; skill with nearest 5.3 and 50%. Generated slides carry about twice the objects of real ones. · `check` now reports objects per slide against the archive's range (CLUTTERED above its 90th percentile), the share of objects matching nothing the archive has drawn, and boxes them in red (novel_*.jpg).
- 2026-11-16 · Existing kit checks weren't being used · The owner asked why the OOH word counter and other kits weren't used. The OOH 7-word rule is for road signs and would flag every real piece (median 19 words), so a feed needs the archive's own copy length; the test prompts only said "use whichever kits help", so agents used core and type only. · `check` now runs a copy-length check against the archive (COPY HEAVY above its 90th percentile), says which kits it applied and which are still the agent's (type, backdrops, social rules), and the core skill's fast path names the kits to use. Realistic prompts should name them.
- 2026-11-16 · Prompt enhancement as step 0 · The owner: the skill should list and refer to the relevant kits itself, and tell a person's Claude to enhance the prompt first. Test prompts that only said "use whichever kits help" left agents on core and type. · `studio.py brief "<prompt>"` is a deterministic router (keywords to job, kits, engines, files, rules, checks; no archive needed) and step 0 of nazar-core/SKILL.md says to run it, show the brief in one block and ask only what is missing.
- 2026-11-16 · Targeted questions · The owner: a polished prompt should pass straight through, and a thin one should be questioned only where it is missing something. `studio.py brief` now ends with up to four questions with options and a recommended pick (where the work is, which exact files and where each may go, which backdrop for which content, what each piece says, what must never appear, the voice), skipping anything the prompt or the saved profile already says; none for a polished prompt.
- 2026-11-16 · Usage rules and the colour drift · Colours stayed on the archive's palette in every run (a pixel-vocabulary test: real 0.1% off, generated 0 to 0.2%, a purple default 94.6%), but the accent drifted: runs told by `chain_check` to "darken the blue for new type" set #0552C7 and #0564CF instead of #3589E7. · The advice now says move the line or use the brand's ink, never recolour. New `usage.py`: backdrop match passed its known-answer test (purple default flagged 4 of 4, runs that used the exact files 0 of 6) and is a check in `studio.py check`; colour roles per element and ground, and mark positions, did not discriminate (real held-back pieces flagged about as often as generated ones, because the archive varies) and are reported as guidance in `learn`, not enforced.
